What I learned:

I saw several instances of a forEach method being called on an ArrayList in places
where a for loop could do the same The type of the parameter passed into
this ArrayList.forEach method is a "Consumer<T>" where T is the type of the objects
that the ArrayList contains. What ArrayList.forEach ends up doing is calling the given
Consumer on each individual element of the ArrayList [1].
For instance, the variable players (which is an ArrayList that
contains objects of the type Player) has forEach called on it in the line

players.forEach(p -> p.heal(1));

and inside the parentheses of the forEach call, p -> p.heal(1) satisfies the type of the argument
that ArrayList.forEach requires. This p -> p.heal(1) is a lambda expression [2], and counts as a
Consumer that accepts a Player object in terms of the players.forEach call because the lambda
expression accepts a Player object and returns nothing (Player.heal has a void return type). You would
use forEach to replace a bulky for loop. One situation where I could see myself using a forEach loop
instead of a conventional for loop is if I need to do some complex operations item-wise on a list and then
do something with the individual items.

Program Modification:

I added the ability for the player to charge an attack, and after the player has charged up,
their next attack will deal double damage. I wanted to add more variety to what actions the
player could take, so a buffing action seemed like a good idea to add, especially since
the player already can choose to attack, guard, or use a potion. To implement this, I changed
both Player.java and Game.java. I added an instance variable called charged to Player.java and a
setter for that variable in order to have the Player objects remember if they are charged or not,
and I modified attack() so that it returns the correct amount of damage if the player was charged
and removes the charged state if the damage should be doubled. I also modified Main.java in 2 ways:
I added the option for the player to charge up an attack in the switch case statement that handles
player action (and also displayed that action as a possible action to take) and used a forEach loop
that runs at the end of combat to uncharge any player that was still charged at end of combat.
A major challenge I had while working on this assignment was figuring out how the main game loop
worked so I could insert my code to reset the charged state at the right spot. While the code itself
was documented, there are a lot of nested loops so it was extremely crucial to find the right loop
to reset the charged state.
